🧩 7. Why we have both Entity and Domain Entity

This is intentional.

For Project:

Project

is our business/domain object.

While:

ProjectEntity

is our Dataverse persistence representation.

They should not be treated as the same thing.

For example:

Domain                       Dataverse
────────────────────────────────────────────
Project                  →   ProjectEntity
ProjectId                →   Guid
ProjectStatus.Active     →   Choice 121930001
WorkspaceId              →   EntityReference

The Mapper is responsible for this translation.

🧠 8. Why the Mapper is particularly important

We encountered this exact issue with WorkItem.

Your domain says:

WorkItemType.Task = 1;

But Dataverse says something like:

Task = 121930000

The domain should not know about 121930000.

Instead:

WorkItemType.Task
       │
       ▼
WorkItemMapper
       │
       ▼
121930000
       │
       ▼
Dataverse Choice

Likewise on GET:

121930000
       │
       ▼
WorkItemMapper
       │
       ▼
WorkItemType.Task

This is exactly why we're using the Mapper layer.

🟠 9. Where DataverseContext fits

This is the one part I want you to understand clearly.

We originally had:

DataverseContext

doing several jobs:

DataverseContext
 ├── Create
 ├── Retrieve
 ├── Update
 ├── RetrieveMultiple
 ├── Mapping
 └── Dataverse communication

That worked, but it made the infrastructure layer less clean.

We then moved toward:

IDataverseClient
       │
       ▼
DataverseRepositoryBase
       │
       ├── Create
       ├── Retrieve
       ├── Update
       └── RetrieveMultiple
              │
              ▼
            Mapper

That's a cleaner separation.

🧱 11. Standard template for every future feature

From now on, when we add another aggregate — for example Conversation, Knowledge, Artifact, etc. — we should follow this template:

1️⃣ Domain
   ├── Entity/Aggregate
   ├── Value Objects / IDs
   ├── Enums
   └── IRepository

2️⃣ Application
   ├── Commands
   │   ├── Create
   │   └── Update
   │
   └── Queries
       ├── Get
       └── List

3️⃣ Infrastructure
   ├── Entity
   ├── Mapper
   └── DataverseRepository

4️⃣ API
   ├── Endpoint
   ├── Request DTOs
   └── Response DTOs

5️⃣ DI
   ├── IRepository → Repository
   └── IRepositoryMapper → Mapper

6️⃣ Dataverse
   ├── Table
   ├── Columns
   ├── Choices
   └── Relationships

7️⃣ Swagger testing
   ├── POST
   ├── GET by ID
   ├── PUT
   └── LIST
